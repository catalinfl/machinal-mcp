# machinal recipe workflow

Start with get_editing_reference(topic=brief) or machinal://reference/brief. Before authoring a new video, ask about missing type/goal, duration, aspect and output resolution, visual sources/style and audio/text, then wait for the user's reply. Use the host's native question tool (OpenCode: question), grouping unanswered choices in one questions array with short headers and concrete options, not a numbered chat questionnaire; use an unnumbered chat fallback only if no interactive tool is available. Recommend a useful image/animated-scene/footage option when undecided; do not re-ask answered questions or override 'you decide'. After the user answers, summarize the agreed brief briefly and proceed immediately with the authorized work in the same turn. Do not ask for a separate plan confirmation or approval of each covered stage. Include known permissions as separate explicit questions in the same form where possible; reuse actual source-use/spending permission for the same scope, never infer it from creative choices or a cancelled form. Do not automatically add production labels or repeated AI disclaimers to the video/chat; be honest about generated media and resolve a requested or specifically required disclosure once. Brief choices do not authorize media access or paid work.

For exact media tool arguments and transfer/recovery decisions, first read get_editing_reference(topic=media) or machinal://skills/media. A freshly supplied client-local file goes to the server volume; a cloud source is reused after consent. Give a requested opaque download link; perform a client-local download only when requested. A server/container volume is not the client's filesystem.

Narrated edits have a timing checkpoint: after source-use/spending approval, submit speech and requested captions alone with generate_assets, wait for completion and read get_job_result. No image/scene jobs belong in that first submission. Use returned measured audio/caption times to author visuals in a second composition, retaining resolved voice assets, resultAssetId, resultTextIds and texts. See examples narration-timing then narrated-documentary. sourceJobId is only for unchanged continuation, not adding visuals. Do not invent cues, add unrequested TTS/captions or regenerate successful timing work; an incomplete/failed timing pass blocks dependent visuals.

Runtime estimates from the user or AI are approximate unless an explicit hard duration cap is given. For a planned 30-second video with 38–40 seconds of successful narration, extend the video with longer/recompiled scenes or relevant additional client-authored scenes; keep the voice, caption results and existing images. Do not regenerate, truncate or speed up narration to fit an estimate. Update placements/overlaps to cover the measured audio end, state the adjusted runtime and proceed without reconfirmation within approved visual/spending scope. Resolve an explicit hard duration cap or spending limit before changing paid narration or exceeding approval.

1. list_projects (or create_project). Ask permission before listing existing media; request_media_access can prepare the question but does not grant permission. After consent, list_media(projectId, userApproved=true, storage=s3|volume|all); follow nextOffset. Listing is separate from approval to download/use named files.
2. Read get_recipe_schema and get_capabilities once per schemaHash. Use targeted references for the chosen treatment, and evaluate footage, stills and animated Svelte scenes per beat. Before timing is measured, any beat times are provisional. Use examples as synthetic templates only. Explain a coherent treatment plan, and author a complete local .edit.yaml file with the client's workspace tools, never a JSON recipe.
3. New sources: first discover list_local_media for an approved local-folder/no-upload request. Configured owner-scoped read-only roots support list_local_media, inspect_local_media (actual bounded raster thumbnails) and import_local_media (local working copies, no network/S3 upload). Disabled/unmounted roots do not permit arbitrary client paths; never change mounts or silently upload without permission. Use returned project filenames with get_asset_metadata and recipes, never root paths. Otherwise get_upload_target and an approved host transfer upload directly to the project volume, not S3. Existing approved S3 sources are hydrated internally to the volume for processing. Never send local paths, binary/base64 video or arbitrary media URLs to recipe tools.
4. After approval to inspect/use the named sources, use get_asset_metadata with userApproved=true and files [{"id":"clip","file":"clip.mp4"}]. Include the returned assets in the composition when validating/compiling.
5. validate_recipe on the exact YAML after every edit, then optionally compile_recipe to inspect the normalized plan/duration. For final rendering require no error diagnostics or unresolved requirements; pending generation requires validation again after materialization. Clip outPoint is source time: outPoint = inPoint + timelineDuration * playbackRate, not start + timelineDuration. version is numeric but optional catalogVersion/compilerVersion are quoted strings such as '1', never numeric 1. Use valid YAML lists, not an ad-hoc emitter; preserve the resolved document and repair only the affected fields. Never use paid rendering to discover syntax/type/overlap errors.
6. Check get_credits. Estimates are approximate and credits are not reserved; report actual usage at the end. Below 30 credits give a brief warning, not an exact advance budget. Pending provider costs do not block unrelated work. When the user authorizes source use and paid work, render_video with userApproved=true and a stable idempotencyKey. Reuse that key and exactly the same composition after an uncertain submission retry; do not ask again for each already-approved stage of the same workflow.
7. Use wait_for_job(timeoutSeconds=120), ignoring heartbeat revisions. If still running after the bounded wait, call again for that same job; do not resubmit work. get_job is for an immediate progress snapshot. Retrieve get_job_result once for resolved YAML, or use sourceJobId for an unchanged next stage. Closing the client does not cancel a job; use cancel_job explicitly. list_jobs recovers recent work.
8. Only status=completed is success. Refresh get_credits and distinguish pending from final costs. After receiving approval, get_video_result(delivery=link,userApproved=true) returns an opaque application link and expiry: give the requested clickable link, not a local path or raw S3 URL. For an explicitly requested local file choose delivery=local, confirm the client-local directory and verify the full download without overwriting. Neither the opaque link nor redirects receive the application key. Expired links are refreshed for the same job, not another render.

Example composition (source clip must have at least four seconds):

    document:
      version: 1
      mode: assemble
      inputs:
        shots: {kind: video, multiple: true}
      sequence:
        use: shots
        each:
          take: {from: 0s, duration: 4s}
          source_audio: remove
      output: {aspect: landscape, resolution: 720p, fps: 30, format: mp4}
    bindings:
      shots: [clip.mp4]

Rendering resolves filename bindings automatically. Validation/compilation should include an assets list from get_asset_metadata, using matching binding IDs (for the example, request id=clip.mp4 and file=clip.mp4).

The current client writes Svelte source and repairs compile_scene diagnostics without another backend AI generation fee. Read get_editing_reference(topic=scene-authoring), scene-runtime and example client-scene; place compiled assets in video tracks. Pending scene.generate/scene.edit are rejected without fallback. get_scene_source and sourceFile preserve attachments for client edits. Source compilation and catalog selection are free; server scene rendering and final video encoding are NOT free and use the configured rendering tariff. Images, speech and captions/transcription also remain billed. generate_assets prepares media without final encoding.

An owned project is an editable timeline plus all of its sources, not a JSON/YAML attachment or only a populated Media Bin. Successful generate_assets and final render_video persist the resolved tracks/clips, audio, captions, effects, transitions, output settings and pinned asset references into that project's saved editor state when its timeline is empty/media-only or the previous prepared timeline is untouched. Manual edits and intentionally cleared documents are preserved; the editor offers Open prepared/rendered timeline with explicit replacement confirmation. get_project must expose the saved timeline, not just filenames. Verify the project after production and report a precise persistence blocker rather than calling a recipe file a finished project. Do not start another render or regenerate assets to save/reopen an existing edit. save_project remains the version-checked operation for complete editor state; never pass it raw YAML or hand-reconstruct captions. Preserve unrelated fields and reconcile 409 conflicts. Large prepared-text/editor states beyond MCP bounds must use REST directly.


CAPTION PRESERVATION: Treat existing YAML captions as read-only unless the user explicitly requests a caption change. Preserve complete caption entries: exact texts[].text and words[].text (including spaces, line breaks, punctuation and diacritics), cue grouping/order, IDs, resultTextIds, sourceClipId, start/duration, word start/end, positions, anchor/align, fonts, sizes, colors, backgrounds and animation/highlighting/effects. Do not paraphrase, correct spelling, trim/collapse whitespace, split/merge/reflow cues, retime, reposition or restyle captions while adding visuals or repairing unrelated diagnostics. Existing caption configuration takes precedence over style profiles, captionMaxWords and four-word/two-line defaults; those defaults apply only to NEW caption generation. The renderer already handles font measurement, fitting, wrapping and collision avoidance: do not simulate that layout by rewriting YAML captions. Adapt scene labels/visuals around the existing caption band, not the captions around new scenes. Keep captions separate, never duplicate/bake them into Svelte or regenerate successful results.

For unchanged continuation use sourceJobId. When adding visuals, patch the resolved recipeYaml from get_job_result, never reconstruct captions from a transcript or summary. Before submission compare the complete caption entries and resultTextIds with that baseline; undo unintended caption changes. Validation/compilation alone does not prove preservation. Only deterministic reversible encoding repair or exact recovery from an intact source is an encoding exception, not permission for editorial/layout changes. If a real caption diagnostic cannot be resolved without changing existing captions, report the specific blocker and ask before changing them. This is an editing rule, not a new YAML lock flag.

TIKTOK CAPTIONS: When the brief targets TikTok or requests TikTok-style captions, NEW captions must explicitly use fontFamily: montserrat and fontWeight: 700 unless the user explicitly chooses another font. This is the supported TikTok-style font used by the deployed TikTok presets, not official TikTok Sans; never invent a tiktok/tiktok-sans font ID. Verify get_editing_reference(topic=fonts,id=montserrat). Set both fields in captions.generate.style before the timing-first pass; for newly authored manual captions use flattened texts[].fontFamily and texts[].fontWeight. A tiktok-pop/tiktok-box/tiktok-glow preset name is not a substitute for an explicit caption font, and captions.generate uses style, not job.preset. Preserve existing caption fonts/configuration unless the user explicitly requests a font change; a TikTok destination alone does not authorize restyling existing captions. Generic portrait/social output does not imply TikTok or permission to add captions.

VIDEO PRODUCTION QUALITY: After the brief, read get_editing_reference(topic=production). Keep the existing scene-engine; this is a director/builder/critic workflow, not a Remotion migration. Before scene code, write a compact production contract from measured cues: subject-specific visible action, independent moving objects, composition/light, reveal/action/hold/exit, adjacent-shot handoff and exact effect/transition targets or a justified cut. Run a focused critic pass against that contract before authoring; a compiling title card is not a successful expressive scene. Correct major design omissions within approved scope, without asking for another plan approval. The current client owns both passes; do not silently call a server critic or spawn another model. Before final render, compare the resolved YAML and Svelte source with the contract. compile_recipe includes editorialReview with actual junctions, looks/motions and expanded effects; status=review_required is NOT aesthetic approval. Implement missing promised treatments instead of dropping them during staging. Intentional cuts/minimal treatments are valid, not excuses for ignoring a bold brief. Inspect available approved frames/video, but distinguish source/plan review from actual visual inspection; no invented inspection tools or unapproved paid review loops. Do not claim a verified visual result when only source/plan was reviewed.

Before new TTS, read list_speech_models once for the narration language, then get_speech_model only for the selected model's voices if needed. Ask for the narration model in the SAME native brief form, not after spending approval, unless the user already chose or delegated that choice. For Romanian recommend google/gemini-3.8-flash-tts and offer google/gemini-3.8-flash-lite-tts as an economical alternative. For English ASK the user: offer hexgrad/kokoro-82m as an economical option, Gemini 3.8 Flash-Lite as a multilingual alternative and Gemini 3.8 Flash for expressive delivery. Do not choose English solely to lower cost. Respect an explicit Gemini 3.8 Flash request; never silently substitute Lite, Kokoro, Gemini 3.1 or another model. Use explicit model, language and compatible voice in YAML. Gemini 3.1 remains legacy compatibility, not the recommendation for new work. Qualitative tiers are not guaranteed credit quotes or measured latency/quality. Selection is separate from source-use and spending consent; do not generate audition samples unasked.

Minimize workflow latency without lowering quality: cache references/schema/capabilities within the workflow; fetch independent required references concurrently, not every guide/preset. Only read exact presets actually used. Discover missing tool signatures once and reuse them. Retain local .svelte source and resolved .edit.yaml; patch only affected fields instead of retransmitting/reconstructing whole documents or rereading a scene you just authored. For unchanged continuation prefer sourceJobId. Submit each independent ready scene once, grouping independent calls when safe, then use bounded waits. Correct ALL reported compiler diagnostics together before resubmission; do not blindly retry unchanged source or keep adjusting one pixel per job. If the same failure remains after two targeted repairs, stop and report the blocker rather than looping. Keep each timed beat's text mutually exclusive and reserve the caption band from the first draft. Do not recompile scenes to bake in paragraphs of captions as a workaround for a text-rendering failure; fix the actual error while preserving timing results. A successful compile/validation of the exact final document is reused, not repeated without edits. Do not use paid renders to discover timing/layout/schema errors. Return the exact opaque download URL from the tool, without rewriting its path/token; refresh delivery for the same completed job on expiry/404, never rerender it. Provider/catalog discovery is not permission for paid probes.

Caption text must remain UTF-8 end to end. Inspect resolved texts[].text AND words[].text for mojibake before rendering; preserve Romanian diacritics (ă â î ș ț Ă Â Î Ș Ț). On Windows use explicit UTF-8 for file reads/writes; never round-trip YAML or tool results through a legacy encoding. The recipe compiler repairs known reversible Romanian encoding damage, including mixed correct/damaged text. Use compile_recipe's normalized document and keep text/word spellings consistent without changing measured timings, IDs or resultTextIds. For invalid_text_encoding or U+FFFD, restore the exact text from an intact transcript or supplied script; never guess lost characters, strip diacritics, regenerate successful speech/captions, or bake captions into scenes to hide the problem. If no intact source exists, report the blocker before paid rendering.

Before inventing a scene effect from scratch, discover the installed client library with get_library_reference(topic=scene-templates), or native machinal_library in OpenCode. Templates are not bundled into this API; direct remote get_editing_reference does not serve them. Fetch only selected editable Svelte IDs and adapt to the real subject/copy, measured timing, aspect and caption band. Templates are starting points, not aesthetic approval or YAML presets. The CURRENT client writes the adapted component and uses compile_scene as usual; no new rendering engine or server-model call. Preserve normal source-use and rendering approvals. Installed library source is versioned; live scene-runtime/schema/capabilities remain authoritative for execution.

FILM STYLE LIBRARY: For cinematic direction, prettier/cinematic animation or a named visual language, use get_editing_reference(topic=film-styles) to discover 66 pinned style prompts; exact id returns reference-only source/provenance. Read topic=film-techniques for selected directing guides or visual helpers and the adaptation guide at machinal://reference/film-styles. The installed machinal-cinema skill includes offline copies. Adapt story, material, staging, camera, rhythm and a native signature action into the production contract, not the demo's story or a generic title card. Native scene-templates include swiss-grid-motion, blueprint-mechanism and paper-stage-3d. Film-style IDs are not YAML presets, workflow-preference style values or compile_scene arguments. Upstream setup/render/TTS/music scripts and caption-layout instructions do not override the deployed runtime, existing captions, source/spending consent or unsupported music generation. Never execute an upstream local pipeline or install its dependencies automatically. Keep current-client Svelte/SceneThree authoring and billed server rendering; no model training or guaranteed visual equivalence. Preserve full existing captions and approved assets/delivery. Source attribution stays outside the video.

HYPERFRAMES COMPONENT LIBRARY: Sources/catalogs ship on the user's PC in @machinal/mcp/library, not this API binary. Use get_library_reference(topic=hyperframes-components), or native machinal_library in OpenCode; get_hyperframes_source (OpenCode machinal_hyperframes_source) reads original pinned files locally. Only nativeStatus=ported entries supply executable Svelte; pending entries are not published. Compile selected adapted source using compile_scene on the configured service. Keep the registered renderer modules compatible; library discovery does not authorize user-media access, generation or rendering. Preserve captions, provenance, substitutions and Apache-2.0/third-party notices. Never execute upstream CLI/installers or add another renderer.

CONTROLLED SCENE ASSETS/CONTINUITY: Only use deployed compile_scene.models support after checking capabilities and source consent: at most two self-contained static GLB v2 attachments, 4 MiB each, embedded PNG textures, no external URIs/extensions/decoders/imported animations/skins/morphs. Use loadSceneModel/loadSceneTexture through tracked async SceneThree setup; never install a local loader, generate a model unasked or silently substitute formats. Read scene-runtime for exact bounds. handoff_scene samples declared deterministic scene.objects states at an exact outgoing source frame and patches exposed incoming parameters into a NEW immutable asset; both named scenes and versions need consent. Keep coordinate/camera semantics compatible; no conversion, inferred pixel pose, transferred timing controls or automatic timeline replacement. Update only the intended asset reference and revalidate, preserving complete captions/audio. Diagnostic inspection plus compilation is free; subsequent rendering is billed. placeAnchoredLabel is a bounded rectangular candidate search, not a universal solver or permission to reflow captions. Neither declared states nor successful compilation prove visual continuity/quality.

COMPLEX SCENE ASSETS BY DEFAULT: When a character, animal, plant, realistic product, detailed object, texture or illustration would not read well as procedural SVG/CSS, default to an image-backed animated scene rather than forcing fragile stacks of shapes or a generic title card. Reuse an approved suitable image first; otherwise plan image.generate within approved generation/spending scope, without waiting for the user to explicitly request an image. Keep SVG/CSS for simple diagrams and genuine SceneThree geometry for spatial action; images complement animation, not a slideshow replacement. Explicit no-generation, footage-only and imagePolicy: procedural-only choices override this default.

VISUAL COVERAGE: Apply this choice when SVG/CSS is overly simplistic as well as when it is complex or fragile. For a documentary/biography, plan distinct subject-specific views of relevant people, geographic context, environments and period-grounded illustrative scenes from verified narration/copy, not one portrait repeatedly surrounded by text, lines and nodes. A useful image-coverage list ties each asset to its measured beat, narrative purpose, reuse/new-generation choice and destination scene. 5–10 distinct images per video can be appropriate; this is neither a quota nor a cap. The four-image attachment limit is per scene, not per video: distribute images across compile_scene calls or ordinary image clips as appropriate. Reframing/recoloring the same portrait is not a new contextual view. Do not choose a simplistic infographic solely to make the video cheap. Reuse suitable successful assets and respect the approved budget; if necessary coverage exceeds permission or a hard spending cap, explain the tradeoff and ask rather than silently downgrading or overspending. Minimal/no-generation/procedural-only briefs still win. Generated historical illustrations are not archival footage or verified evidence.

IMAGE TOOL SELECTION: image.generate is a YAML job type, not an MCP tool. For missing complex or overly simplistic artwork, use generate_assets with approved image.generate jobs after the timing-first checkpoint, not compile_scene to draw a token SVG substitute. Validate the staged recipe, wait_for_job until completed, then get_job_result for actual image filenames and the resolved recipe. Reuse resolved audio/captions/assets; compile_scene then composes and animates the approved images, at most four per scene. generate_assets creates artwork, compile_scene compiles client-authored animation, inspect_scene supplies approved bounded frame diagnostics, and render_video performs paid final rendering; these roles are not interchangeable. Select tools for the current stage and its prerequisites, not every tool for every beat; selection grants no media or spending approval.

For isolated foreground subjects, sprites, cutouts and independently composited layers, default to background: transparent on image.generate. Use openai/gpt-image-2.5-sunburst unless the user selected another compatible model; openai/gpt-image-2.5-flare also supports transparent backgrounds. Respect explicit model choices; do not silently substitute an incompatible model. Request an isolated complete subject, clean edges and real alpha, with no painted checkerboard, solid backdrop, frame or baked-in labels. Use background: opaque for full-frame environments or images whose background is part of the story; transparency is not a blanket default for every image. The image job field is background, not transparent: true; compile_scene.transparent controls the scene canvas separately.

After the timing-first checkpoint when applicable, generate the approved image, wait for completion and use its actual returned filename in compile_scene.images. Preserve PNG/WebP alpha; do not flatten onto a solid background or convert cutouts to JPEG. Animate separate approved image layers and labels independently, respecting the four-image attachment limit; moving one bitmap does not animate its internal parts or reconstruct 3D. A transparency request alone does not verify returned alpha: do not claim verification from a filename, metadata or a JPEG diagnostic thumbnail. If alpha is missing or unverified, report that limitation without automatic paid regeneration or local background-removal pipelines. Reuse existing scope approvals; this creative default never grants media access, paid generation or rendering permission.
